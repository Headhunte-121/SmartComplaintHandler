## 1. High-Level Architectural Purpose

In computer graphics and geographic information systems (GIS), rendering a real-world university campus requires converting physical GPS coordinates (latitude and longitude measured on the curved surface of the Earth) into a 2D Cartesian coordinate plane $(X, Y)$ that an SVG canvas can render with sub-pixel precision.

`campusGeometry.js` is the **Authoritative Cartographic Ground-Truth Dataset** for the IIIT Naya Raipur campus. It was generated by projecting real-world survey-grade GeoJSON features (`IIIT_Naya_Raipur_GIS_Complete.geojson`) onto a standardized $1080 \times 800$ canvas:
1. **True-Scale Equirectangular Projection**: Maps GPS bounds ($21.12^\circ\text{N}, 81.76^\circ\text{E}$) to a $1080 \times 800$ viewbox, preserving angular alignment and aspect ratios.
2. **Exact Building Footprints**: Stores multi-vertex polygon points for all 16 major campus structures (Academic Block, Canteen, Auditorium, Hostels, Sports Complex, Incubation Center).
3. **Internal Wing Geometry & Courtyards**: Models complex architectural shapes like U-shaped academic blocks and open-air hostel quadrangles.
4. **Pedestrian & Vehicular Networks**: Encodes 10 road polylines and 11 pedestrian footpaths with exact lane widths.
5. **Georeferenced Physical Entrances**: Catalogs official building entrance doorways with both canvas coordinates $(X, Y)$ and physical WGS-84 GPS coordinates (`lat`, `lng`).

### Plain-English Purpose
Defines the coordinate system bounds. The master SVG canvas uses a virtual coordinate space $1080$ units wide by $800$ units tall ($1080 \times 800$). `IIITNR_CAMPUS_PERIMETER_POINTS` and `INNER_CAMPUS_CLIP_POINTS` define the outer six-sided perimeter of the university campus property line.

### Line-by-Line Breakdown
- `CAMPUS_VIEWBOX`: Coordinate boundaries passed to the SVG `viewBox="0 0 1080 800"` attribute.
- `IIITNR_CAMPUS_PERIMETER_POINTS`: Space-separated list of coordinate pairs `X,Y` representing the campus boundary fence line.

### Deep Term & Concept Expansion
- **SVG ViewBox vs Viewport**: The `viewBox` defines the internal virtual coordinate space (here $1080 \times 800$), whereas the `viewport` is the actual physical pixel size of the screen (e.g. $1920 \times 1080$ on a laptop or $390 \times 844$ on an iPhone). The browser automatically scales the vector graphics to fit any screen without quality degradation.

## 3. High-Frequency Viva & Technical Defense Questions

### Q1: How was the real-world campus map converted into this SVG dataset?
**Model Answer:**  
The dataset was produced from survey-grade geospatial data (`IIIT_Naya_Raipur_GIS_Complete.geojson`). Ground-truth GPS coordinates (WGS-84 latitude and longitude recorded via satellite surveying) were converted to a 2D Cartesian coordinate plane using an **equirectangular map projection**. The bounding box of the campus was normalized into a standard $1080 \times 800$ pixel canvas, mapping geographical boundaries into exact SVG vector points.

### Q2: Why are roads and footpaths stored as polylines rather than polygons?
**Model Answer:**  
A road network represents linear transit paths with varying widths. Storing roads as SVG `<polyline>` elements with custom `stroke-width` attributes (e.g. `width: 13.3` for two-lane main roads vs `width: 3.8` for walking trails) requires far fewer coordinate points than polygon boundaries, saving memory while rendering clean, anti-aliased curves.

### Q3: What is the purpose of storing `lat` and `lng` inside the `entrances` array?
**Model Answer:**  
While `x` and `y` coordinates position the doorway beacon on the 2D SVG canvas, the `lat` and `lng` properties anchor the doorway to physical GPS reality (e.g., Main Portico Entrance is at `21.128164°N, 81.766357°E`). This enables seamless future integration with outdoor GPS mobile navigation, allowing field technicians to trigger turn-by-turn walking directions to the exact entrance door of an incident.

### Q4: Why are building label coordinates stored separately in `LABEL_POSITIONS`?
**Model Answer:**  
If labels were rendered at each building's centroid (`cx, cy`), text strings would overlap building courtyard geometry or wing outlines. `LABEL_POSITIONS` establishes collision-free coordinate anchors calculated using an iterative force-directed labeling layout, ensuring text labels never obscure physical architectural details.

### Q5: What does the `wings` array represent inside each building object?
**Model Answer:**  
Many campus buildings are not simple rectangles. For example, the Academic Block has multiple interconnected research wings, lecture theaters, and administrative quadrants. The `wings` array stores individual polygon coordinate strings for each structural wing, allowing the digital twin to render complex architectural floor plans accurately.
